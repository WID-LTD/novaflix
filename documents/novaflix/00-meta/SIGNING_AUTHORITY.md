## 3. Execution Procedures

### 3.1 Class A Execution (Corporate Seal Required)

```
1. Document prepared by Legal/Founder
2. Review by Legal Counsel (if available)
3. Founder reviews and approves content
4. Print on company letterhead (or generate PDF)
5. Founder signs: "Success" (cursive) + printed name + title + date
6. Parent Company Attestation block completed:
   - WID Ltd name + RC 8824091
   - CEO: Ike Wisdom
   - Authorized by: Chukwu Akachukwu Success (Founder & CEO)
   - Date
7. Corporate Seal affixed (physical) or digital seal rendered (PDF)
8. Scan executed copy → store in secure repository
9. Enter in Document Register (MASTER_INDEX.json)
```

### 3.2 Class B Execution

```
1. Document prepared by relevant department
2. Review by Legal/Founder
3. Founder signs (digital or wet ink)
4. Parent Company Attestation block completed (no seal required)
5. Execute counterparts if multiple parties
6. Store executed copies
7. Update Document Register
```

### 3.3 Class C Execution

```
1. Document prepared by technical/operational team
2. Founder reviews and signs (digital signature acceptable)
3. Store in version-controlled repository
4. Update Document Register
```

### 3.4 Class D Execution

```
1. Automated generation via build pipeline
2. Watermark applied automatically
3. No manual signatures required
4. Archive with generation metadata
```

## 6. Digital Signature Implementation

### 6.1 PDF Generation Pipeline

```
Markdown (.md) → HTML (styled) → Puppeteer → PDF → pdf-lib
    ↓                                              ↓
Frontmatter (metadata)                    Watermark + Signatures
                                              ↓
                                        Signed PDF + MASTER_INDEX entry
```

### 6.2 Verification

Each signed PDF contains:
- Visual signature block (last page)
- Parent attestation block (last page)
- Corporate seal indicator (Class A)
- Document ID footer (`NFX-<HASH>`)
- Generation timestamp in metadata

### 6.3 Verification Script

```bash
npm run verify
```

Checks:
- Watermark presence on all pages
- Signature block on last page
- Doc ID matches MASTER_INDEX
- Hash integrity

## 7. Legal Validity (Nigeria)

### 7.1 Electronic Transactions Act 2011 Compliance

- Digital signatures recognized under Section 17
- PDF with embedded signatures = valid execution
- Audit trail (MASTER_INDEX) = evidence of execution

### 7.2 Companies and Allied Matters Act (CAMA) 2020

- Section 98: Company seal execution requirements met
- Section 773: Electronic filing with CAC accepted
- Board resolutions in writing (digital) valid per Section 264

### 7.3 Evidence Act 2011

- Computer-generated documents admissible (Section 84)
- MASTER_INDEX.json serves as register of execution

### 8.1 Lost Signing Authority

If Founder unavailable:
1. Board resolution appointing alternate signatory
2. Parent company (WID Ltd) CEO (Ike Wisdom) executes
3. Document registered with "Emergency Execution" notation

### 8.2 Document Dispute

1. Verify Doc ID against MASTER_INDEX
2. Check signature block timestamp
3. Confirm parent attestation
4. Corporate seal verification (Class A)
5. Escalate to Lagos High Court (Commercial Division) if needed
